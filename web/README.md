# web/ —— 结果查看器

> **一句话：把 `findings_ai.json` 变成人能看、能筛、能拿去讲的东西。**

单文件，零依赖，**可离线** —— 比赛现场不一定有网，所以这里不引任何 CDN、
不用任何框架、不需要任何构建步骤。

## 怎么跑

```bash
python web/serve.py
```

它会起一个只监听本机（127.0.0.1）的静态服务并自动打开浏览器。
数据自动去找 `out/findings_ai.json`，找不到就退到 `out/findings.json`。

> **为什么不直接双击 `index.html`？**
> 浏览器不允许 `file://` 页面读取本地文件（CORS 限制）。这是浏览器的规则，
> 不是程序出错。真要走这条路也行 —— 页面会提示你把 JSON 拖进去。

## 两条契约要求，这里是落实点

### 1. `decided: false` 必须显示出来

`core/schema/README.md` 规定：**前端和报告必须把 `decided: false` 显示出来，
不许静默填一个默认算法。**

详情页的「迁移 / 加固结论」区块就是干这个的 —— 它把 `decided` 和
`source` 原样打出来，不藏。

### 2. 四种「给不出结论」要分开说

原先 `decided: false` 同时表示「用途判不出」和「规则库没这条」，
但这两件事对用户是完全不同的消息。现在 `reason` 把它们分开了，
查看器按不同颜色和措辞显示：

| `reason` | 显示 | 意思 |
|---|---|---|
| `decided` | 🟢 已给结论 | 规则库给了确定建议 |
| `usage-undetermined` | 🔵 用途待定 | **§9.1 的正确行为**，不是缺陷 |
| `not-an-algorithm` | ⚪ 非算法命中 | 命中的是 Provider 名 / 配置项 |
| `rule-missing` | 🟠 规则库未覆盖 | 该补 `core/rules/` |
| `not-enriched` | ⚪ 尚未增强 | 还没经 `ai/` 处理 |

## 它同时是契约的验收工具

**这一点比"好看"重要。** 契约里要求的字段在这里必须能渲染出来 ——
渲染不出来的地方，就是契约的缺口。

`reason` 这个字段当初就是被逼出来的：读数据的时候发现
「用途判不出」和「规则库没这条」在 UI 上根本没法分开显示。

## 自检

```bash
node web/selftest.js                  # 喂 out/findings_ai.json
node web/selftest.js findings.json    # 喂 scanner 的原始产出
```

用最小 DOM 桩把 `index.html` 的脚本跑一遍，断言**渲染出来的 HTML 里
有没有该有的东西**（不需要浏览器、不需要装依赖，有 node 就行）。

两种数据都要能看：**已增强的**（有 AI 解释和真建议）和**未增强的**
（scanner 的占位符，只有 `reason: not-enriched`）。

> ⚠️ 这个自检自己踩过一次坑，写在 `selftest.js` 文件头：最初 fetch 桩
> 「哪个候选文件存在就给哪个」，于是永远先命中 `findings_ai.json` ——
> 传 `findings.json` 时两次渲染的是同一份数据，却一路 PASS。
> **桩比被测代码宽松时，测试就失去证伪能力。**

## 没做的（明确记下来，免得以为是漏了）

- **没有导出报告** —— 计划里有，待做
- **没有 `evidence_refs` 跳转** —— 该字段 schema 里还没有（已知缺口）
- **没有后端** —— 不需要；数据已经是结构化的
