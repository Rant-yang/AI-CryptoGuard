# web/ —— 结果查看器

> **一句话：把 `findings_ai.json` 变成人能看、能筛、能拿去讲的东西。**

单文件，零依赖，**可离线** —— 比赛现场不一定有网，所以这里不引任何 CDN、
不用任何框架、不需要任何构建步骤。

## 怎么跑

```bash
python web/serve.py
```

它会起一个只监听本机（127.0.0.1）的静态服务并自动打开浏览器。
数据自动去找 `out/findings_ai.json`，找不到就退到 `out/findings.json`。

> **为什么不直接双击 `index.html`？**
> 浏览器不允许 `file://` 页面读取本地文件（CORS 限制）。这是浏览器的规则，
> 不是程序出错。真要走这条路也行 —— 页面会提示你把 JSON 拖进去。

## 视觉口径（答辩时用得上）

这些不是审美偏好，每一条都有理由：

**浅色，不是暗色。** 答辩要投影。暗色 UI 在亮房间里暗部被压缩、发灰 —— 正文会糊掉。
底色用冷白（`#f4f6f8`）而不是纯白或米色：纯白投影刺眼，米色是 AI 生成页面的常见胎记。

**等宽体是默认嗓音。** 算法名、文件路径、行号、计数、编号 —— 全用 Consolas。
这个工具的材料本身就是标识符和十六进制，等宽体是它的母语。
中文解释性文字才切成无衬线（等宽的中文读起来累）。全页只有这两个字体，**不引 web font**
—— 现场可能没网。

**五种风险按「成因」分色，不按轻重。** 这是全项目的论点：`shor`（量子直接破解）和
`broken`（经典攻击已破）是**两回事**，上游工具把它们混为一谈（CryptoScan 把 MD5 判成
"量子脆弱"，判错了）。所以两者都是红，靠**三重**区分：

| 通道 | shor | broken |
|---|---|---|
| 明度 | `#c93a2b` 亮 | `#7e2f24` 暗 |
| 纹理 | 实色 | **斜纹** |
| 文字 | 量子直接破解 | 经典攻击已破 |

第三个通道是关键 —— **颜色永远不是唯一通道**，灰度打印或色觉障碍下信息不丢。
配色全部按「配白字 ≥4.5:1」选过（WCAG AA）。

**hero 上那句「与量子无关」。** 威胁构成条不只是画个比例，它把每类的**机制**写在下面。
`broken` 那格的机制就是项目的核心主张，直接摆在首屏。

**只有一处动效。** 载入时色条从左展开一次（450ms），表示构成在累积。
其余没有任何淡入、滑入、悬停位移 —— 那些是"一眼 AI 生成"的典型特征。
`prefers-reduced-motion` 下全部关闭。

## 两条契约要求，这里是落实点

### 1. `decided: false` 必须显示出来

`core/schema/README.md` 规定：**前端和报告必须把 `decided: false` 显示出来，
不许静默填一个默认算法。**

详情页的「迁移 / 加固结论」区块就是干这个的 —— 它把 `decided` 和
`source` 原样打出来，不藏。

### 2. 四种「给不出结论」要分开说

原先 `decided: false` 同时表示「用途判不出」和「规则库没这条」，
但这两件事对用户是完全不同的消息。现在 `reason` 把它们分开了，
查看器按不同颜色和措辞显示：

| `reason` | 显示 | 意思 |
|---|---|---|
| `decided` | 🟢 已给结论 | 规则库给了确定建议 |
| `usage-undetermined` | 🔵 用途待定 | **§9.1 的正确行为**，不是缺陷 |
| `not-an-algorithm` | ⚪ 非算法命中 | 命中的是 Provider 名 / 配置项 |
| `rule-missing` | 🟠 规则库未覆盖 | 该补 `core/rules/` |
| `not-enriched` | ⚪ 尚未增强 | 还没经 `ai/` 处理 |

## 它同时是契约的验收工具

**这一点比"好看"重要。** 契约里要求的字段在这里必须能渲染出来 ——
渲染不出来的地方，就是契约的缺口。

`reason` 这个字段当初就是被逼出来的：读数据的时候发现
「用途判不出」和「规则库没这条」在 UI 上根本没法分开显示。

## 自检

```bash
node web/selftest.js                  # 喂 out/findings_ai.json
node web/selftest.js findings.json    # 喂 scanner 的原始产出
```

用最小 DOM 桩把 `index.html` 的脚本跑一遍，断言**渲染出来的 HTML 里
有没有该有的东西**（不需要浏览器、不需要装依赖，有 node 就行）。

两种数据都要能看：**已增强的**（有 AI 解释和真建议）和**未增强的**
（scanner 的占位符，只有 `reason: not-enriched`）。

> ⚠️ 这个自检自己踩过一次坑，写在 `selftest.js` 文件头：最初 fetch 桩
> 「哪个候选文件存在就给哪个」，于是永远先命中 `findings_ai.json` ——
> 传 `findings.json` 时两次渲染的是同一份数据，却一路 PASS。
> **桩比被测代码宽松时，测试就失去证伪能力。**

### 两次「断言测错了东西」

**一、断言在测实现形状，不是不变量。** 原本有一条 `概览用了风险配色`，
写法是「`#stats` 里出现 `var(--shor)`」—— 那其实是在断言色值被**内联**进了 HTML。
后来配色改由 `.seg.<risk>` 这条 CSS 规则给出，内联写法没了，断言就失效并报错 ——
但界面明明是对的。改成两头都验：段带对类名，且样式表里该类名确实绑到同名变量。

**二、断言跟着数据走，就漏掉没出现的那一类。** 改完后断言只遍历「数据里出现过的」
风险值。而当前数据集里 `review` 是 **0 条** —— 于是没人发现 `.seg.review`
这条 CSS 规则**根本没写**。一旦扫出 `review` 的条目，那一段会是**没有底色的空白**。
现在改成：凡 `RISK_CN` 里定义了的风险，样式表都必须有 `.seg` / `.rk` 规则，
**与当前数据无关**。抽掉这条规则，断言立刻报 `review`；装回去就过。
