## 对本项目评测的意义

该表主要标注 API 用途或误用上下文；本项目 Finding 的正式计数单位是 `(文件, 算法, 用途)`。原表并没有为所有案例给出稳定的算法名、用途枚举及同文件所有密码使用的完整负例清单。源码 JAR 还可能在一个文件里包含表格未标出的其他调用。直接扫描 8 个 JAR 的全部源码，再把未列出的检出统统计作 FP，会制造错误的 Precision；把 121 条直接当作完整同口径独立留出集也不成立。

它仍可用于**另行预注册的真实项目专项诊断**：先核对完整包名、源码版本与行号，再固定范围和逐实例匹配规则；只报告通过人工核对的那部分实例及该专项的分母。若用它作 Java 深度证据演示，也须明确第三方 CrySentry、样本来源以及 `partial` 污点证据的边界。该来源目前不替代仍缺的全系统同口径独立留出集。
