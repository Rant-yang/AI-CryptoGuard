## 生成候选报告

本机先安装 `python-docx`。在仓库根目录的 **Windows cmd** 中运行：

```cmd
python docs\build_submission_report.py --template C:\path\to\official-design-report.docx --draft -o C:\path\to\AI-CryptoGuard-report-draft.docx
```

脚本读取[作品说明书候选内容](作品说明书_候选版_2026-10-18.md)，沿用官方封面和基本信息表，生成匿名草稿；清空作者/公司属性，并移除官方模板继承的 WPS 自定义数据（其中含编码的用户标识）及相关 ZIP 引用，保留醒目的 `【待填系统编号】`。草稿不是最终可提交文件。

平台分配编号后，**先人工复核报告内容与版式**，再用实际编号生成：

```cmd
python docs\build_submission_report.py --template C:\path\to\official-design-report.docx --number 实际平台编号 -o C:\path\to\编号-2026密码竞赛复赛作品设计报告.docx
```

脚本拒绝覆盖已有输出，`--number` 只接受字母、数字和连字符；若平台编号有其他字符，先核对官方格式再调整脚本。审批及签字页仍须由队伍按官方模板填写、签署、盖章和单独上传；脚本**不会**代填、伪造签名或单位信息。

## 生成后的人工验收

1. 用 Word/WPS 打开，检查封面、分页、表格宽度、中文字体、页眉页脚与全部页面是否完整；当前 v17 候选已在本机 Word 导出为 **6 页 PDF**，全部 6 页视觉核查了封面、信息表、正文、表格分页和评测表，未见明显裁切；最终版仍须逐页重审。**最终内容和实际编号填入后还要重做视觉审阅。**
2. 全文、隐藏属性、图片和附件均不得暴露参赛单位、队员、老师等身份；模板提醒段必须已经删除。第三方工具的必要出处不应冒充团队身份。
3. 表格中的数字须与最终冻结的评测记录一致；开发集与独立测试、首次结果与同集回归分开写。若最后几天测试数据改变，先改内容源，再重新生成候选并复核。
4. 核对平台编号在报告首页和最终文件名中一致；设计报告、支撑材料、审批签字页各传到正确的位置。[提交总清单](复赛提交核查_2026-10-18.md)。
