# 复赛提交核查（2026-10-18）

> **官方时限优先于初期方案：** [2026 第十一届全国密码技术竞赛复赛通知](https://www.chinacodes.com.cn/news/lookAllNews.do)规定，提交窗口为 **2026-10-19 09:00 至 10-22 18:00**。早期文档中的「10-23 前提交」是错误日期。建议 10-21 完成内部冻结；这只是团队安排，不是官方规则。

## 1. 三份材料分别准备

| 材料 | 官方文件名格式（扩展名按平台模板） | 匿名要求 |
|---|---|---|
| 作品设计报告 | `编号-2026密码竞赛复赛作品设计报告` | 网络评审匿名；不得出现学校/单位名称及简称、领队、指导老师、队员等身份信息 |
| 相关支撑材料 | `编号-2026密码竞赛复赛相关支撑材料` | 同上；官方大小上限 **4 GB** |
| 审批及签字页 | `编号-2026密码竞赛审批及签字页` | 按官方附件模板单独提交，不与匿名报告/支撑材料混放 |

`编号` 由参赛平台在选题后生成，须写在设计报告首页和上述文件名中。当前仓库不知道团队编号，**不能猜一个编号**。队长在平台核实编号与要求的格式，再命名和上传。

已从官网下载的“复赛通知附件.zip”中核对附件三原件（独立 DOCX，仓库外保存）：除编号、作品题目和三名队员的贡献排序/任务分工/亲笔签字外，模板还留有**指导老师签署推荐意见**、**所在单位或部门盖章**及日期。队长应尽早联系相关人员办妥；本仓库不会伪造签名或把含姓名的签字页放入匿名设计报告、支撑材料或 Git 仓库。签字页使用平台指定的单独提交位置，上传后核对回执。

## 3. 提交前逐项核验

1. 按官网附件二、附件三取得并使用**当年**模板；确认平台编号，检查报告封面。
2. 对设计报告、PPTX、支撑包执行匿名审阅：正文、封面、图片、截图、页眉页脚、文件名、压缩包内路径、Office/PDF 作者属性、示例命令和日志都要检查。学校/单位、个人姓名、账号、`C:\Users\...` 等本机账户路径不得泄露；第三方机构的**必要来源引用**应与团队身份区分。
3. 支撑包不要带 `.git/`、`.env`、`workspace/`、`out/`、真实凭据、原始扫描结果、可逆匿名映射、CrySentry/JDK 二进制或未经授权的外部 benchmark。校验第三方许可证与来源说明。
4. 材料内每个指标说明输入、计数单位、首次测试还是同集回归。25 例 Java 算法专项深扫 P/R **没有提升**（历史 14/4/2，当前扫描器快/深均 14/5/2）；另一个预注册 7 文件弱密钥专项首次深扫新增 4 TP/1 FP，修正 `<clinit>` 解析后的**同集回归**为 5/1/0，**不能**把回归当作第二次独立结果或合并为全系统 P/R。旧版 30 条和历史 35 条是不同输入批次，两批结构合规均**不是**语义正确率；修复后批次 29 条算法 Finding 的独立人工盲审仍为 0/29。异机部署、两次团队完整彩排未完成时如实写未验证。
5. 先在本机解压/打开最终文件，跑安装和演示命令；核对支撑材料大小不超过 4 GB。上传后从平台查看/下载回执与文件，确认三个位置都正确，再结束提交。不要卡到 18:00。

## 4. 本地三材料核查门

### 拿到平台编号后的单命令候选出包

先把最终报告内容、答辩 PPTX 和源码改动提交到 `main`，从参赛平台**核对真实作品编号**，将当年官方报告模板存放在仓库外。以下命令在仓库根目录的 Windows cmd 中执行；先把 `set` 行右侧换成平台给出的真实编号，不要拿测试编号上传：

```cmd
set "ACG_NUMBER=平台实际编号"
python setup\prepare_submission.py --number %ACG_NUMBER% --template D:\code_competition\_official\作品设计报告模板.docx --slides docs\AI-CryptoGuard-答辩候选版.pptx -o D:\code_competition\_submission\%ACG_NUMBER%
python -m setup.prepare_submission_selftest
```

模板路径按本机实际位置修改。命令拒绝脏工作区、仓库内输出目录和已有目录；它从**已提交 HEAD**生成匿名源码，按编号生成匿名 DOCX 和单附件支撑 ZIP，并对三种原件及合包运行正式机器核查。仅在全部通过后才发布输出目录；失败的临时文件会清理。输出目录含 `编号-2026密码竞赛复赛作品设计报告.docx`、`匿名源码.zip` 和 `编号-2026密码竞赛复赛相关支撑材料.zip`。源码 ZIP 已包含在支撑 ZIP 内，勿在平台上重复上传；平台如果要求分别上传多个附件，须按平台页面调整。**本命令不生成审批签字页，不检查图片像素或未知身份信息，也不上传。**正式上传仍需团队逐页看最终报告/PPTX、核对签字页及平台回执；任一源文件改动后重新提交并重新出包。

### 逐项核查命令（排错时使用）

`setup/submission_audit.py` 同时检查匿名报告 DOCX、答辩 PPTX 和匿名源码 ZIP。草稿阶段可用 `--draft`（允许报告保留醒目的编号占位符）；**正式上传前必须改用平台实际编号运行 `--number`**。命令示例在仓库根目录的 Windows cmd 中运行：

```cmd
python setup\submission_audit.py --draft --report C:\path\to\report-draft.docx --slides docs\AI-CryptoGuard-答辩候选版.pptx --source C:\path\to\anonymous-source.zip
python setup\support_bundle.py --number 实际平台编号 --slides C:\path\to\final-slides.pptx --source C:\path\to\anonymous-source.zip -o C:\path\to\实际平台编号-2026密码竞赛复赛相关支撑材料.zip
python setup\submission_audit.py --number 实际平台编号 --report C:\path\to\实际平台编号-2026密码竞赛复赛作品设计报告.docx --slides C:\path\to\final-slides.pptx --source C:\path\to\anonymous-source.zip --support C:\path\to\实际平台编号-2026密码竞赛复赛相关支撑材料.zip
python -m setup.submission_audit_selftest
```

核查门会拒绝：正式报告文件名或正文编号错误、模板提醒段未删、Office 自定义/隐藏 XML 与非空幻灯片备注、已知团队账号或本机账户路径、源码包清单/哈希错误、输出或二进制混入。它**不能**识别图片像素中的姓名、未知姓名、个人照片、语义上间接暴露单位的信息，也不能代替队员逐页人工匿名审阅、平台上传回执或审批页签署。`--draft` 通过仅表示三份**候选文件**满足机器能检查的项目，并非可直接提交。

带 `--support` 的正式核查还会检查支撑材料 ZIP 的官方文件名、清单、编号、SHA-256 和内部两份文件是否与刚刚审阅的 PPTX/源码包**完全相同**。源码或幻灯片一旦更新，必须重建合包并重跑核查；上传前仍要人工打开外层 ZIP 检查内容。测试编号 `ACG-TEST-2026` 走过“生成报告→合包→四项正式核查 PASS”预演，测试文件已清理；这不等于已拿到真实平台编号或完成正式上传。

此清单仅是本项目的核查表；官方通知和平台页面若更新，以官方最新要求为准。
