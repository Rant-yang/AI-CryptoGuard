# 量子危机时间窗口与 HNDL 评估

更新时间：2026-10-15。负责人：C。状态：**已实现并接入统一入口与 Web**。

## 1. 它解决什么问题

“RSA 受 Shor 威胁”只说明技术风险，不回答“什么时候必须开始迁移”。时间窗口模块在前置量子风险评估中增加业务时间维度：

- X：数据或安全属性还需要保持有效多少年；
- Y：系统完成盘点、改造、联调和上线需要多少年；
- Z：组织采用的量子威胁时间窗是多少年。

当 `X + Y >= Z` 时，系统给出 `urgency=immediate`；否则给出 `years_until_action=Z-X-Y`。三个数字必须由用户或组织政策提供，系统不预测 Q-Day，AI 也不允许代填。

## 2. 它在流水线的位置

```text
快速扫描 / Java 深度证据
        ↓
密码学量子风险评估（Shor / 量子搜索 / 不适用）
        ↓
量子危机时间窗口（X/Y/Z + HNDL）
        ↓
AI 用途解释与具体整改
        ↓
Web / 报告
```

时间窗口属于 C 的确定性规则层。A 的深度证据可以增强数据流定位，B 的 AI 可以解释结论，但二者都不负责计算公式或编造参数。

## 3. HNDL 怎么判断

HNDL 是“现在收集密文，将来量子能力成熟后解密”。系统将它与普通迁移紧迫度分开：

- 签名用途不按密文 HNDL 评估；
- 加密或密钥交换用途，且用户确认存在可收集的流量/存档时，继续比较 X 与 Z；
- `X >= Z` 时标记 `at_risk`；
- 用途或暴露情况不清楚时保持 `unknown`，不猜。

## 4. 怎么运行

网页：运行 `python web/serve.py`，展开“量子危机时间窗口”，同时填写 X/Y/Z，并选择 HNDL 暴露状态。

命令行：

```cmd
python core\pipeline.py D:\待扫描项目 ^
  --tools-dir D:\code_competition\_smoke ^
  -o out\run ^
  --data-lifetime-years 10 ^
  --migration-lead-years 3 ^
  --threat-horizon-years 8 ^
  --hndl-exposure yes
```

不传参数时，Finding 仍会生成，但时间状态为 `not_configured`，页面明确显示没有时间结论。

## 5. 输出字段

任务级输入保存在 `task.json.quantum_timeline_profile`。每条 Finding 的结果位于 `quantum_assessment.quantum_timeline`，包括：

- `status`：assessed / not_configured / not_applicable；
- `urgency`：immediate / scheduled / unknown / not_applicable；
- X/Y/Z 与 `years_until_action`；
- `hndl_exposure` 与 `hndl_status`；
- `rule_refs`、输入来源和明确前提。

时间参数进入 AI 输入摘要，因此 X/Y/Z 变化后，旧 AI 解释不会被错误复用。

## 6. 当前边界

- 当前时间窗口只对 Shor 直接威胁的传统公钥密码下结论；量子搜索类问题不套用同一公式。
- X/Y/Z 是场景参数，不是从源码中可以可靠推导的事实。
- `unknown` 和 `not_configured` 都是有效结果，不应为了页面好看填默认值。
- 本功能给出迁移启动紧迫度，不宣称预测量子计算机何时具备破解能力。

## 7. 验收

```cmd
python core\quantum_timeline.py
python core\selftest.py
python web\server_selftest.py --integration
node web\selftest.js out\run\findings_assessed.json
```

公开小样例实测（X=10、Y=3、Z=8、HNDL=yes）：44 条 Finding；13 条进入 Shor 时间评估并判为 immediate；其中 3 条为 HNDL at_risk。该数字只证明功能闭环，不代表真实项目风险比例。
