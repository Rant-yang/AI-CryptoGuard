> 状态：2026-10-18 的**提交材料草案**，供队伍审阅；不是已验收的最终作品说明。官方提交截止为 **2026-10-22 18:00**，建议 10-21 内部冻结。正式设计报告与支撑材料须按[官方复赛通知](https://www.chinacodes.com.cn/news/lookAllNews.do)完成匿名检查，使用平台编号；审批及签字页单独提交。所有数字都注明样本、计数单位和首次/回归属性。

## 1. 作品摘要

AI-CryptoGuard 面向项目源码中的密码使用风险，提供“快速发现 → 可选 Java 深度证据 → 本地量子风险评估 → 可选 AI 用途解释与整改步骤 → 中文报告”的流水线。用户上传源码项目后可在 Web 页面查看任务状态、问题位置、证据引用、风险原因、迁移候选和待人工确认事项；也可从命令行运行和导出离线 HTML 报告。

本项目**不宣称自研了三个底层扫描器**。CryptoScan、cbom-scan 和 CrySentry/Tai-e 的检测能力属于各自原作者。团队自研的是调用与隔离、不同输出的归一化与保守融合、凭据与局部源码规则、用途约束的量子迁移决策、AI 证据引用与隐私保护、评测管线及界面。第三方来源和实际分发边界见[声明](第三方来源与分发边界.md)。

## 2. 解决的问题

现成工具的输出在术语、风险口径、路径与严重度表示上不同，同一处密码调用可能重复出现，也可能被错误地归为“量子可破”。例如已经被**经典攻击**淘汰的 MD5、DES 与受 Shor 算法威胁的 RSA/ECC 不应写成同一种原因。直接将原始发现交给大模型，又容易把“看到了某算法”误推为“已经知道业务用途”，甚至无依据地把 RSA 固定映射到某个 PQC 算法。

系统因此分开处理三类判断：扫描器提供证据；本地规则裁决确定性密码事实；AI 只在证据支持范围内解释用途、未知项与可执行的核查步骤。证据不足时写 `unknown`，不编造用途或传播路径。

## 3. 架构和数据流

```text
源码项目 ──→ 快扫：CryptoScan / cbom-scan / 本地规则
    │                           │
    └─ Java 且用户提供编译产物 ──→ CrySentry（可选）
                                ↓
                       统一 Finding + E1/E2… 证据
                                ↓
                   本地量子风险、迁移时间窗口评估
                                ↓
                    AI 用途解释与整改步骤（显式启用）
                                ↓
                     中文 Web / 离线 HTML 报告
```

快速模式支持 Python 和 Java 等项目；Java 深度模式还需要用户已编译的 jar/classes、JDK 17 和仓库外 CrySentry。工具缺失、编译产物不匹配、超时或零可达方法时，任务明确写 `skipped`、`failed` 或 `timeout`，不把失败当作“没有问题”。入口和参数见[用户手册](用户手册.md)。正式 v0.2 格式及状态约定见[共享契约](../core/schema/CONTRACT_V0.2.md)。

一条 Finding 按文件、归一化算法及用途收口，多个工具的不同位置保留在 `evidence[]`。`E1` 指第一条证据，`evidence_refs` 必须引用本条 Finding 中真实存在的编号。CrySentry 仅给首尾位置时，flow 标 `partial` 或 `source_missing`；没有中间节点就不展示完整传播链。无法可靠映射的深度记录进入任务的未解决区，不伪造源码行。

统一入口把 `scan`、`deep_java`、`quantum_assessment`、`ai` 四个阶段写入任务状态；仅在相应阶段真实完成时标 `completed`。Java 深扫需要与源码对应的已编译产物；Python 仍走快扫和本地 AST/常量规则，`deep_java=skipped`。深度工具失败不删除快扫发现，成功也不把“深度工具没报”解释为“快扫误报”。证据融合保留每个工具的来源、行号及可信范围，扫描原文与可逆匿名映射不进入最终报告。

量子评估在 AI 之前由本地规则执行。它分别记录 Shor 对公钥用法的威胁、Grover 对对称安全强度的影响、经典攻击已淘汰的算法和证据不足项；凭据类问题不当作 PQC 迁移。迁移路线先看实际用途：签名与密钥交换/封装不同，用途未知时只列条件候选。时间窗口可选输入 X（数据保护期）、Y（迁移准备期）、Z（组织采用的威胁时间窗）：`X+Y≥Z` 才给“应立即启动”提示；不填参数则显示 `not_configured`，系统不预测量子计算机出现日期。HNDL 仅在加密/协商及暴露条件有证据时评估。

AI 只解释证据支持的用途、风险原因、未知项与整改步骤；密码事实及迁移算法由本地规则复核。判断和步骤须引用本条 Finding 的 `E1/E2…`。旧批次曾把调用误归给资产证据；现显式标注证据编号，并要求实际调用才能确定用途。TLS 版本赋值只证明配置角色，不能证明握手；`createECDH`、`Signature.getInstance` 和 `Cipher.getInstance` 仅创建对象，不能单独证明密钥协商、签名或加密。云端 AI 需显式开启且先脱敏；失败时保留本地扫描和量子评估。

修正上游 `DESede` 误标、ECDH 与签名/加密构造器用途门槛后，先登记、再对同一批公开样例运行当前 v7：44/44 条解释完成（29 条算法调用模型、15 条凭据本地处理），0 最终失败、0 结构错误。算法用途为 unknown 24、hashing 4、tls_configuration 1；无实际交换证据的 ECDH 保持 unknown，不选定 ML-KEM。29 条私有盲审包已生成，**人工语义审阅 0/29**。这是同集回归，不是独立语义正确率；旧批次单独保存。

公开 Java 样例还验证了用途证据的实际作用：原先只有 `Cipher.getInstance` 时模型保留 `unknown`；补上同一变量 `Cipher.init(ENCRYPT_MODE)` 的本地调用形状和行号后，真实模型给出 `encryption`，引用 `E1/E3/E4`。这只证明配置为加密模式，不等于 `doFinal` 执行或实际业务影响，见[单例复验](Java加密用途证据复验_2026-10-18.md)。

## 4. 核心功能与原创边界

| 功能 | 当前实现与边界 |
|---|---|
| 多源证据 | 快扫归一化、算法别名与跨工具保守融合；Java CrySentry runner 和适配器由本项目编写，**底层数据流引擎是第三方**。公开 Java 样例的深扫、量子评估及 AI 解释四阶段已真实跑通，见[集成验收](AI-v0.2集成验收_2026-10-18.md) |
| 凭据检测 | 八类本地规则已编码，报告只保存指纹/遮蔽结果；专项开发语料效果仍不足以宣称独立达标，见[专项记录](凭据检测_2026-10-14.md) |
| 量子风险和迁移 | 区分 Shor、公钥用途、Grover 削弱、经典已淘汰与证据不足；签名与 KEM 的迁移路线由规则库按用途分派，算法未知时暂不给具体路线；X/Y/Z 和 HNDL 为用户输入的假设场景，非预测日期 |
| AI 解读 | 显式启用；调用前白名单脱敏，输出结构化引用、用途、解释、未知项与未执行整改步骤；凭据原文不上云，确定性密码结论由本地规则给出。旧 28 条批次曾有 2 条引用错位；当前 v7 在公开样例同集回归中 44/44 结构通过，其中 29 条算法走模型、15 条凭据留本地，**算法人工语义盲审仍为 0/29**。结构通过不代表解释正确 |
| Repair → Verify | 三类 Python 候选补丁只在临时副本执行；语法、正式扫描器复扫、自建演示项目测试已通过；[Chimera nonce 第三方正向案例](第三方正向修复验证_2026-10-18.md)的上游同一模块 45 条测试前后均通过。源文件不改；全项目、真实网络协议及其他模板仍需人工复核与进一步验证 |
| Web 与导出 | 项目上传、阶段状态、问题与证据卡片、离线中文 HTML；原始扫描输出不直接作为静态文件暴露 |

ProwlBench 首次结果之后，我们补充通用 JSON/YAML 凭据键值和静态 HTTP Basic 头检测；**同一冻结集首轮回归**为 P=92.06% / R=42.78%。随后对敏感语境中的长随机值加入保守兜底，**第二轮同集回归**为 P=92.74% / R=47.36%，仍漏检 3,523 个正例。两轮回归均不是新的独立成绩。第二轮改动前后对同一开发三语料的凭据组件评分均为 TP/FP/FN=190/6/32；它与另行报告的算法＋凭据整体开发指标不是同一个单位，也不能替代独立泛化验收。

旧版 30 条与 28 条公开样例揭示证据引用错位和 TLS 配置角色误判；44 条 v5/v6 批次又揭示 `createECDH` 与签名/加密构造器被误当作实际使用。按修订门槛复验的当前 v7 在同一公开开发集上 44/44 结构通过，**29 条算法人工盲审仍为 0/29**。各版是问题发现与同集回归，不得混算或把结构成功说成语义准确率。逐版记录见[旧批次](AI语义验收_2026-10-18.md)、[TLS 回归](AI_TLS配置角色同集回归预登记_2026-10-19.md)、[DESede 纠错](AI_DESede修正后盲审预登记_2026-10-19.md)、[ECDH 门槛](AI_ECDH实际调用门槛复验预登记_2026-10-19.md)与[当前 v7](AI_构造器用途门槛复验预登记_2026-10-19.md)。

评测时先固定样本来源、标签、匿名化映射和匹配单位，再运行工具；匿名化会去除文件、类和目录名中直接泄漏答案的词，同时保留真正的代码字面量。开发语料的算法 Finding 按文件与算法匹配，凭据 Finding 按文件与 benchmark 宽泛类别匹配；后者不能证明八个细分类别各自达标。安全资产清单不等于风险 Finding，范围外正例及仅落在其上的输出按同一规则处理。OWASP 行按文件统计；ProwlBench 行只按代码片段中是否存在秘密计分，亦非八类管理缺陷分别评价，因此都不能与开发语料合并计算“总准确率”。ProwlBench 首次冻结过程和标签定义差异见[独立诊断](ProwlBench凭据首次诊断_2026-10-18.md)。

运行时间也按实验边界报告：固定 25 例 Java 对照在本机快扫约 0.7 秒，CrySentry 单独约 6.9 秒；项目编译耗时不在其中。公开 `activemq` smoke 曾约 15 秒。这些样本不足以证明任意中小型项目都能在方案目标的 30 秒内完成。失败、超时和 `skipped` 阶段进入完成率记录，不能按“零发现”混入 Precision/Recall。

## 6. 隐私、安全与第三方分发

- 默认在本地扫描；只有用户显式开启 AI 才请求云服务。上云前经白名单脱敏；绝对路径、疑似密钥、token 和上游 raw 不直接发送。公开/自有项目可选经脱敏的上下文，敏感项目使用仅调用形状模式。
- 检出的凭据不写原文到日志或报告，默认只留指纹/遮蔽提示。临时任务可删除。`workspace/`、`.env`、`out/`、原始 benchmark 和可逆匿名映射均不提交。
- CrySentry 为 LGPL-3.0 第三方工具，当前仅在仓库外构建和进程调用；提交源码包不包含其源码、fatJar 或 JDK。若将来改变分发方式，必须重新核对实际二进制来源、许可证、NOTICE 与修改记录。
- 自动修复只是候选操作，不在用户原项目执行；修复结果即使复扫消失，也必须结合项目测试、业务兼容性及人工确认。

## 8. 冻结前必须补齐的证明

这份候选稿不能直接当作“所有目标已完成”的最终材料。按方案第 20、21 节，至少还需：

1. 一批在运行前封存、未用于调规则、与目标计数单位一致的独立留出样本；首次结果与后续回归分开报告。已核查的外部候选及其不能直接做真值的原因见[来源核查](外部Java评测源核查_2026-10-18.md)。
2. 八类凭据各自的独立真值与检出效果；不能用总体 P/R 替代专项。
3. 当前 v7 批次 29 条算法 Finding 的人工用途、引用、事实与步骤评价；未审完前不写语义通过率。历史批次单独保存、不得混算。
4. 已有一例独立第三方项目的正向 Repair→Verify 模块测试（Chimera nonce，45 条上游测试前后通过）；仍需另外两类模板的第三方正向测试，以及全项目和真实协议兼容性核查，不能把单模块通过写成任意项目可自动部署。
5. 异机部署记录、实际最终打包清单与许可证复核、两次有操作者和日志的全程彩排。

更新本稿时，要逐项链接新证据；没有证据的条目保持“未验证”，不根据期望结果补数字。
