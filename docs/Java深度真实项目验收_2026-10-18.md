# CrySentry 真实 Apache Java 模块验收（2026-10-18）

这次验证的是**第三方项目上的运行与证据融合**，不是独立 Precision/Recall
评测。样本来自 [ApacheCryptoAPI-Bench](https://github.com/CryptoAPI-Bench/ApacheCryptoAPI-Bench)
提交 `7cb0feac079471de21a85f369d03d250dba0b137` 所附的
`directory-server/kerberos-codec` 源码 jar 和编译 jar；第三方源码、jar、原始结果均
保存在主仓库外，没有提交或分发。源码 jar 解出 475 个 Java 文件，编译 jar 与之
对应。没有执行该项目的构建脚本。

## 运行方式与结果

在本机先用 `setup/preflight.py` 检查同源 Java 文件、编译产物、仓库外 CrySentry
fatJar、JDK 17 及快速扫描工具，14 项全部通过。用 `core/pipeline.py` 的
`--mode deep-java` 对提取的源码目录运行；`--java-artifact` 指向该模块编译 jar，
`--crysentry-home` 与 `--crysentry-java` 指向仓库外工具。没有启用云端 AI。

| 项目 | 真实运行结果 |
|---|---:|
| 快速扫描 Finding | 45 |
| 深度阶段状态 / 耗时 | `completed` / 11.622 秒 |
| CrySentry 已定位记录 | 30 |
| 最终 Finding / v0.2 契约 | 45 / 45 条有效 |
| 已挂载 CrySentry pattern / taint 证据 | 18 / 5 |
| 未能唯一挂载的深度线索 | 5 |
| taint 的完整性 | 5 条均为 `source_missing`，**无完整传播路径** |
| 新增独立 Finding | 0 |

这说明 runner 能在真实第三方编译产物上完成分析，并把可定位的证据挂到统一报告。
它**没有证明检测率提高**：该仓库主表 121 条标签混有随机数、证书、HTTP、参数误用
与算法风险，且约 50 条在所附源码 jar 中找不到唯一对应源码。没有按我们的
`(文件, 算法, 用途)` 单位冻结可比子集、匿名化和盲测之前，不计算或宣称 P/R。

进一步核对上游 `ApacheCryptoAPI-Bench_detail_list.xlsx`：主表 121 条中，仅 71 条能在
随仓库提供的 8 个 `*-sources.jar` 中找到唯一源码，50 条找不到；当前跑通的
`kerberos-codec` 模块源码树（475 个 Java 文件）只覆盖 36 条标签。**即便找到源码，
标签中的行号也不能直接用作该 jar 的准确位置。**例如表里把
`HmacMd5Checksum.java:26` 标为 `Mac.getInstance("HmacMD5")`，但附带源码 jar 的
第 26 行是 `import javax.crypto.SecretKey;`，真正的调用在第 50 行。若用第 26 行
去匹配扫描证据，会把正确发现误判为漏报。标签的“Crypto context / Non-Crypto
context”也不是我们的“密码风险”二值真值，另有 `Non-vulnerable context`。
因此该语料目前只能作为第三方**运行与错误分析样本**；若要计分，必须先逐条
对齐源码版本、调用点和真值含义，并冻结一个公开说明的子集。这与 OWASP 的
文件级诊断及开发集的 `(文件, 算法, 用途)` 指标分别报告，不能混加。

## 发现并修复的归一化缺口

首次运行时 CrySentry 把 JCE 常量 `ARCFOUR` 作为新算法报告；由于
`scanner/normalize.py` 没有这个别名，新增两条 `risk=review` 的 Finding，
尽管 `core/rules/algorithm_risk.py` 已将同义的 RC4 判为 `broken`。
现在 `ARCFOUR`、`ARC4` 均归一为 `RC4`。同一目标重跑后，ARCFOUR 证据挂到
现有 RC4 Finding，两条不一致的新 Finding 消失；最终 45 条而非 47 条，
RC4 风险均为 `broken`。原始字面量仍保留在该条证据的
`raw.algorithm_constant`，以便审计。`scanner/selftest_crysentry.py` 增加了
这一跨模块回归断言。重跑中的 45 条 Finding 和 `task.json` 均通过
`core/schema/validate_v02.py`。

**边界：**此次是检查过结果后的修复与同集回归，不能把 45 条和证据数包装为
独立留出成绩。该模块涉及 Kerberos 等多处密码调用；源码未针对基准命名进行
匿名化，本次也没有启用 AI，因此不能用于 AI 盲评。5 条 taint 只有汇点而没有
来源位置，不展示为完整 source→sink 链。
