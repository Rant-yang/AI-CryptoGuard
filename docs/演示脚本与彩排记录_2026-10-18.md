# 三段演示脚本与彩排记录（2026-10-18）

这是比赛展示的**可执行脚本**，不是已完成两次彩排的证明。三段分别覆盖：
凭据/弱密码、Java 深度证据、抗量子用途分派。全部源码为仓库内原创、故意不安全
的公开夹具；第三方工具和 JDK 位于仓库外。正式彩排前，先按
[用户手册](用户手册.md)和[部署说明](../setup/README.md)完成预检。

下列命令均为 **Windows cmd**，在 `D:\code_competition\AI-CryptoGuard` 根目录执行；
另一台机器应替换绝对路径。`out/`、编译 jar、原始扫描输出不进 Git。

## 开场（约 30 秒）

> “我们把现成开源工具的发现归一成带证据的 Finding，再做本地量子风险与时间
> 窗口评估。AI只解释证据能支持的实际用途和整改步骤；具体迁移算法由规则库
> 约束。网页能从本机项目扫描到中文报告。第三方分析器不是我们自研的。”

不报独立留出 P/R 已达标；开发集和不同单位的 OWASP 诊断数字见
[评测口径](性能与评测口径.md)。

## Demo A：凭据与弱密码（约 2 分钟）

```cmd
cd /d D:\code_competition\AI-CryptoGuard
python setup\preflight.py --tools-dir D:\code_competition\_smoke --target examples\repair_demo --mode fast
python core\pipeline.py examples\repair_demo --tools-dir D:\code_competition\_smoke -o out\demo_a
python core\schema\validate_v02.py out\demo_a\findings_assessed.json
python core\report.py out\demo_a\findings_assessed.json -o out\demo_a.html --task out\demo_a\task.json
```

本机实扫有 **4 条 Finding**：1 条本地凭据、2 条 MD5、1 条弱随机配置。
打开网页时可把 `examples\repair_demo` **作为文件夹**上传；报告详情展示 E 编号，
凭据值不能显示在屏幕/日志。不要说“4 条都经过云 AI”：默认 AI 阶段是 `skipped`，
凭据始终本地处理。需要展示候选修复时另运行：

```cmd
python repair\verify.py examples\repair_demo\app.py --project-root examples\repair_demo --tools-dir D:\code_competition\_smoke -o out\demo_a_repair.json
```

讲清楚修复只落在临时副本；自建项目测试和复扫通过不等于对任意真实系统自动
安全修复。

## Demo B：Java 深度证据（约 2 分钟）

先编译与源码对应的 jar，**不把 jar 提交到仓库**：

```cmd
mkdir D:\code_competition\_demo_java
"D:\code_competition\_smoke\jdk17\jdk-17.0.20.1+1\bin\javac.exe" -g -d D:\code_competition\_demo_java examples\java_deep_demo\Demo.java
"D:\code_competition\_smoke\jdk17\jdk-17.0.20.1+1\bin\jar.exe" --create --file D:\code_competition\_demo_java\demo.jar -C D:\code_competition\_demo_java .
python core\pipeline.py examples\java_deep_demo --mode deep-java --tools-dir D:\code_competition\_smoke --java-artifact D:\code_competition\_demo_java\demo.jar --crysentry-home D:\code_competition\_smoke\CrySentry --crysentry-java D:\code_competition\_smoke\jdk17\jdk-17.0.20.1+1\bin\java.exe -o out\demo_b
python core\schema\validate_v02.py out\demo_b\findings_assessed.json
```

本机复跑：`scan/deep_java/quantum_assessment` 均 `completed`，最终 **2 条
Finding**：`JAVA-WEAK-PRNG-KEY` 有 CrySentry `taint` 证据；AES-ECB 有模式证据。
前者仅定位来源与汇点，没有完整传播路径；展示时把 `partial` 说清楚。
若深度阶段超时或失败，展示快速扫描和 `task.json.stages` 的真实状态，不能
冒充深度完成。JDK 必须是 17；源码与编译 jar 必须同版本。

## Demo C：用途决定抗量子路线（约 2 分钟）

```cmd
python core\pipeline.py examples\pqc_demo --tools-dir D:\code_competition\_smoke --data-lifetime-years 5 --migration-lead-years 2 --threat-horizon-years 4 --hndl-exposure yes -o out\demo_c
python core\schema\validate_v02.py out\demo_c\findings_assessed.json
python core\report.py out\demo_c\findings_assessed.json -o out\demo_c.html --task out\demo_c\task.json
```

本机实扫有 3 条 `shor` Finding：`RSA/signing`、`ECDH/key_exchange`、
`ECC/unknown`。演示重点是前两条选不同的**条件性迁移路线**，第三条用途不明
则列候选并要求确认，不做“RSA 永远换某一个 PQC”的映射。X=5、Y=2、Z=4
使样例时间窗口显示 `immediate`；**这三个数是假设输入，不是量子危机日期预测**。

`core/usage_evidence.py` 只在源码同变量真实出现签名/协商消费调用时补一个
不含源码的证据位置。公开样例单条真模型调用中，RSA 可归 `signing`，ECDH
可归 `key_exchange`；AI 默认关闭，若现场启用须确认端点可用与云端授权。
现场网络不稳时展示本地评估和已导出的 HTML，并明示 AI `skipped`。
当前同一行通用 ECC 与具体 ECDH 仍可能分成两条，不能声称完全消重。
