## 1. 这个项目做什么

```
   一个代码项目
        ↓
   现成的开源扫描工具        ← 不是我们写的（见「三条红线」第 2 条）
        ↓
   我们做：统一整理           ← core/
        ↓
   我们做：AI 解读            ← ai/
        ↓
   报告 / 修复建议 / 迁移建议
```

**我们不自研密码扫描器。** 我们的作品是中间那两层：把三个各说各话的工具
对齐成统一的证据格式，再用 AI 把它解读成人能看懂、能执行的结论。

## 3. 术语表（新人必读）

这些词在我们这儿的意思**和字面意思不一定一样**，看不懂后面全是雾。

| 词 | 在本文档里的意思 |
|---|---|
| **密码资产 / CBOM** | 代码里用到密码算法的地方。CBOM = CycloneDX 1.6 定义的密码资产清单格式 |
| **Finding** | 一条统一格式的发现。所有工具的输出最后都要变成 Finding |
| **Evidence（证据）** | 一条 Finding 底下挂的原始证据（哪个工具、哪个文件哪一行、原文是什么）。多源融合后一条 Finding 可能挂多条证据 |
| **`E1` / `E2` / `E3`** | 不是文件！是**证据的编号**：`E1` = 该条 Finding 的 `evidence[0]`，`E2` = `evidence[1]`，以此类推。AI 的每条结论必须用它们指明「我这句话是从哪条证据推出来的」 |
| **`algorithm_normalized`** | 算法名的归一化形式：全大写、去掉所有非字母数字。`SHA-1` / `sha1` / `SHA1` 都是 `SHA1`。不归一，跨工具对齐全部失效 |
| **`usage`（用途）** | 这个算法被用来干嘛：签名 / 加密 / 哈希 / 密钥交换 / 认证 / TLS 配置 / unknown。**判不出来必须写 `unknown`，不许猜** |
| **risk 五档** | `shor`（量子可破）/ `broken`（经典已破）/ `grover`（量子仅折半，非紧急）/ `review`（拿不准）/ `safe`（健全）。**取最严重的一档** |
| **PQC** | 抗量子密码。签名 → ML-DSA / SLH-DSA；加密、密钥交换 → ML-KEM |
| **口径** | 「这个数是怎么算出来的」的完整约定。**在这个项目里口径比数字重要** —— 同一个代码，换口径数字能差一倍 |
| **范围内 / 范围外** | 基准测试的类别里，我们**建模了的**叫范围内；没建模的参数、部分凭据、TLS 配置等叫范围外。范围外不进召回率的分母 |
| **标注样本 / benchmark** | 别人做好的、带正确答案的漏洞代码集。我们用 4 个：`cryptoapi-bench`、`cambench-cap`、`cambench-real`、`llmcmt` |
| **匿名化** | 跑分前把文件名、目录名、源码里的答案线索抹掉 —— 否则等于把答案喂给大模型，数字全是假的 |
| **主源 / 补充源** | cbom-scan 是**模式证据主源**（三个工具里唯一量子风险分类正确的），CryptoScan 是补充源 |

## 10. 三条红线

改代码前先确认没违反：

**1. 禁止让 AI 自由生成「该换成什么算法」**

方案 §9.1 明文禁止 `RSA → 固定某一种 PQC` 的映射。正确做法是两段式：
LLM 只判断用途 → 规则库查表给算法 → 判不出来就明确说「暂不给出具体算法」，不许猜。

**2. 第三方能力不表述为自研**

| 能力 | 来源 |
|---|---|
| 源码级密码模式扫描 | 第三方（cbom-scan / CryptoScan） |
| Java 字节码数据流分析 | 第三方（CrySentry，**LGPL-3.0**，444MB，永不入库） |
| 统一证据格式与融合裁决 / 规则库 / 凭据检测 / Python AST / AI 语义解读层 | **自研** |

**答辩时必须能说清哪些是调用、哪些是我们写的。**

**3. `workspace/`、`.env`、扫描产物永不入库**

扫描产物含**绝对路径**（信息泄露），凭据类结果可能含**明文凭据**。
`.gitignore` 已挡，但 `git add -f` 能强行绕过 —— **别那么干**。

**另外几条**：`core/schema/` 开了 `additionalProperties: false`，**谁偷偷加一个字段，
所有人的校验全部失败** —— 觉得字段不够用就告诉 C，由 C 改。
A/B 永远不要往 `main` 推。不要用 GitHub 网页版的「新建文件 / 上传文件」按钮
（绕过分支直达 main，已经犯过两次）。
