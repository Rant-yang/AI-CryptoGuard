# OWASP Benchmark Java 独立诊断：首次锁定结果

日期：2026-10-18。目的：用**未参与前期规则开发的外部语料**检查泛化情况。
这是首次结果的固定记录；读到这组结果后进行的任何针对性修正，都只能叫
“在 OWASP 上的回归”，不能把修正后的分数继续称作独立留出成绩。

## 数据与口径

- 来源：[OWASP Benchmark Java](https://github.com/OWASP-Benchmark/BenchmarkJava)，
  checkout `bc5ffeb09fb18ab039806d84ca1f718c2e332c54`，官方 `expectedresults-1.2.csv`，GPL-2.0。源码与标签均置于仓库外，
  不再分发或混入本项目自研代码。
- 从官方 CSV **预先固定全部** `crypto` 和 `hash` 两类，共 **482 个文件**：
  `crypto` 130 真 / 116 假；`hash` 129 真 / 107 假。没有按扫描结果剔除难题。
- 扫描树只含这些编号 Java 文件，平铺在中性目录；不复制官方 CSV 或按类别命名的目录。
  Java 源码本身保留原样，含 `/crypto-00/`、`/hash-00/` 等类别字样；它们只泄漏类别，
  不泄漏正负真值。本次**未调用 AI**，仅测本地快速扫描。
- 官方真值单位是“**这个测试文件运行时是否存在弱密码/弱哈希误用**”；
  本次判定单位是“该编号文件是否有至少一条问题 finding”。这是按文件的专项诊断。
  它与本项目开发语料的 `(文件, 算法, 用途)` 匹配口径不同，**不允许直接对比**
  两套 Precision / Recall，更不允许把它包装为完整系统（含凭据、AI、Java 深度）的成绩。
- 仅运行 `scanner/scan.py` 的两个外部快扫工具与本地规则；`--no-raw --no-coverage`。
  扫描成功：cbom-scan、CryptoScan、本地字面量、凭据扫描均完成，未发生降级。

| 类别 | TP | FP | FN | TN | Precision | Recall |
|---|---:|---:|---:|---:|---:|---:|
| crypto | 130 | 27 | 0 | 89 | 82.8% | 100.0% |
| hash | 89 | 0 | 40 | 107 | 100.0% | 69.0% |

扫描产出 312 条 Finding，分布在 246 个文件；由于主指标按**文件**计算，

这说明“开发集 87.7% / 90.8%”不能直接宣称为独立泛化成绩；
按 OWASP 文件级专项口径，召回低于方案的 90% 门槛。

## 已定位的共同盲点

这 27 个 FP 与 40 个 FN 的源码**全部**含有 `Properties.getProperty(...)`。
抽查官方 `benchmark.properties` 后，可解释两种相反错误：

1. `BenchmarkTest00059.java` 是官方 `crypto=false`，源码写
   `getProperty("cryptoAlg2", "AES/ECB/PKCS5Padding")`，但配置给出
   `cryptoAlg2=AES/CCM/NoPadding`。当前扫描只读 Java 文件里的默认值，
   把它报成 `AES-ECB`；没有解析运行时配置。注意：如果实际部署时配置缺失，
   默认 ECB 本身仍有风险，因此这是**以官方运行配置为准**的 FP。
2. `BenchmarkTest00003.java` 是官方 `hash=true`，源码默认 `SHA512`，但配置是
   `hashAlg1=MD5`。当前扫描看不到运行时生效的 MD5，形成 FN。

这不是“再加几个算法关键词”能解决的。下一步若实现通用的 Java
`Properties.load(...)` + `getProperty(key, fallback)` 常量解析，应在报告里并列写：
“首次独立结果”与“针对此盲点的回归结果”，且再找一批未据此调参的样本复核。
解析失败时应给 `unknown/review`，不把默认值当作已确定的生效配置；
同时保留默认值可能生效的条件性风险，避免假阴性。

## 复现（Windows cmd）

先在仓库外克隆官方语料：

```cmd
git clone --depth 1 https://github.com/OWASP-Benchmark/BenchmarkJava.git D:\code_competition\_benchmarks\OWASP-BenchmarkJava
git -C D:\code_competition\_benchmarks\OWASP-BenchmarkJava rev-parse HEAD
```

下面命令假定 `D:\code_competition\_smoke` 下有 CryptoScan 和 cbom-scan，
且留出集目的目录**尚不存在**；`prepare` 遇到已有目录会拒绝覆盖。

```cmd
cd /d D:\code_competition\AI-CryptoGuard
python benchmark\owasp_holdout.py prepare D:\code_competition\_benchmarks\OWASP-BenchmarkJava D:\code_competition\_benchmarks\_owasp_holdout_source
python scanner\scan.py D:\code_competition\_benchmarks\_owasp_holdout_source --tools-dir D:\code_competition\_smoke -o out\owasp_holdout.json --no-raw --no-coverage
python benchmark\owasp_holdout.py score D:\code_competition\_benchmarks\OWASP-BenchmarkJava D:\code_competition\_benchmarks\_owasp_holdout_source out\owasp_holdout.json
```

脚本要求扫描树与全部 482 个标签文件完全一致，否则直接报错；
`out/`、语料及标签不提交。复现时 `rev-parse HEAD` 必须等于
`bc5ffeb09fb18ab039806d84ca1f718c2e332c54`；若上游主分支已变，
请先检出该提交，再运行 `prepare`。

   不猜测的配置证据，再回归这批样本。

   OWASP 这批数据从此只能作为开发回归集。
