## 冻结评分规则

**计数单位是文件**：每个官方测试文件只计一次。扫描结果必须有 `risk=broken`，且归一化算法名为 `MD2`、`MD4`、`MD5` 或 `SHA1`，才算“报出弱哈希”。同文件多条该类 Finding 仍只计一次；其他类别 Finding 计入 `ignored_other_findings`，不得把它们当弱哈希的假阳性，也不得冒称它们已被评估。

对 71 个 true、80 个 false 分别数 TP/FN、FP/TN。Precision=TP/(TP+FP)，Recall=TP/(TP+FN)。当无报出时 Precision 为 `null`。**这个文件级弱哈希专项指标不能与本项目 `(文件, 算法, 用途)` 开发语料指标合并，不能称为全系统独立 P/R。**

`prepare` 只复制固定的 151 个源码文件到仓库外的新目录，并写出各源码文件哈希的 manifest。`score` 要求文件清单和逐文件哈希完全一致；既防漏扫，也防跑分后改源码。

| 同一冻结 151 文件 | TP | FP | FN | TN | Precision | Recall |

| **首次独立诊断（原扫描器）** | 37 | 0 | 34 | 80 | 100.0% | **52.1%** |
| **针对漏检修复后的同集回归** | 71 | 0 | 0 | 80 | 100.0% | 100.0% |

首次 34 条漏检全部含 `hashlib.new('md5'/'sha1')` 字面量；37 条已检出正例走的是其他调用形态。原 Python AST 规则只检测弱随机，而且本机 Python 3.11 无法解析这 151 个样例中较新语法的 f-string，因此整文件跳过。修复新增窄范围词法回退：只有能证明 `hashlib` 已导入且参数是字面量弱哈希时，才产出证据；`partial-parse` 标签和 `parse_scope=token_fallback` 明示**未完成整文件 AST 分析**。151 个文件在本机均触发该语法不兼容；回退额外产生的 34 条全部对应官方正例。

这轮回归是**看了本集合漏检后才开发**，绝不可把 100%/100% 称作第二次独立成绩或整个系统的 P/R。它只证明这个明确的 Python 弱哈希构造已被覆盖。它没有验证弱随机、凭据、Java、AI 语义、其他 Python 语法，也没有证明运行时可达性。初次与回归的扫描输出都只在本机 `C:\Users\lenovo\acg_holdout_python_hash\`，均通过 v0.1 Schema 校验。

同一 151 文件还通过统一入口跑了**本地 fast → 量子评估**（AI 与 Java 深度显式 `skipped`）；71 条 `findings_assessed.json` 和 `task.json` 均通过 v0.2 契约校验。此链路验收不改变上表的评测口径，也不构成 AI 质量验收。
