## 已验证的范围

原有三类 Python 修复模板只用自身的正则检查“问题消失”，这种检查会重复实现逻辑，
不能作为独立验证。现在可用 `--tools-dir` 对**临时副本**分别运行正式 scanner，
并对照 MD5、硬编码口令、弱随机三类的覆盖状态。

| 类别 | 模板/语法 | 正式 scanner 前后对照 | 结论 |
|---|---|---|---|
| `hashlib.md5` → `sha256` | 已通过合成自检 | 合成例和公开代码例均 `ELIMINATED` | 仅证明扫描器不再报 MD5 |
| 硬编码口令 → 环境变量 | 已通过合成自检 | 合成例 `ELIMINATED` | 仅证明扫描器不再报硬编码口令 |
| `random.Random` → `SystemRandom` | 已通过合成自检 | `ELIMINATED`（后续补充） | Python AST 只识别安全变量接收的 `Random().randbytes`；合成例在正式扫描器前后复扫中消失 |

公开代码例使用仓库外 `cryptoscan-src/crypto-samples/crypto_samples.py` 的
`hash_md5` 函数。结果：原文件 SHA-256 指纹不变，临时副本语法 PASS，
正式 scanner 的 MD5 发现消失，新增 HIGH=0；`tests: NOT_RUN`。
它是第三方演示源码，**不是独立真实项目验收**，也没有项目测试。

后续新增 `--project-root` 可选测试钩子：在两份受限的临时项目副本分别执行
项目 `tests/` 中的 unittest，只保存状态和测试数。仓库内自建
`examples/repair_demo` 演示项目的三项测试在补丁前后均为 **3/3 PASS**，
三类正式复扫均为 `ELIMINATED`，新增 HIGH=0；原文件保持不变。
另有旧 MD5 协议长度断言的反例，补丁后测试明确 **FAIL**。
这些只证明测试钩子能发现一部分兼容性破坏；**仍未在独立第三方项目中完成验收**。

报告新增 `verification_scope`、`independent_scan`、`scanner_rescan`、
`manual_review_required: true` 和 `behavioral_compatibility: NOT_VERIFIED`。
未提供工具目录时 `new_high_findings` 为 null，而不是凭空给 0。
CLI 退出码 0 仅表示结构性复扫成功；不表示补丁可安全部署。

## 为什么仍未达到最终 Repair→Verify 目标

后续加固：修复器过去用全文件正则替换，会修改注释/字符串中的 `hashlib.md5`
等文本；`ast.parse` 也未拦住把 `import os` 插在 `from __future__` 之前的补丁。
现在模板先按 AST 位置编辑、再用 `compile` 做真正的编译级语法检查；
带 Unicode 源码、注释/字符串和 future 导入的回归测试已通过。三类原有
正式 scanner 前后复扫与自建项目 3/3 单元测试仍通过。**这只修复候选补丁的
结构性可靠性，不等于独立第三方项目兼容性验收。**

替换 MD5 会改变输出长度和依赖协议；环境变量修复需要部署环境提供值；
弱随机类已补上限定形态的独立 AST 扫描证据，但仍没有真实项目的构建/单元测试。
现阶段只做临时副本候选修复，绝不改用户原文件。

2026-10-18 追加收窄：原实现只要看到同一文件中的 `random.Random(...)` 就会全部
替换，即使该调用用于可复现模拟、与密码 nonce 无关。现在只编辑“安全用途命名变量
直接接收 `random.Random(...).randbytes(...)`”的构造器；同文件普通模拟源保留，
`random` 名称重绑定时保守跳过。新增反例自检，正式 scanner 三类修复复扫仍均
`ELIMINATED`，自建演示项目 3/3 测试前后通过。这个改动降低误改范围，**不补足
独立第三方项目正向兼容性证明**。
方案 §10 的演示项目单元测试路径已接通；独立第三方项目的构建/测试与完整
行为兼容性仍缺失。
下一步需要一份可公开复现、带测试的 Python 项目，先固定预期行为，
再在临时项目副本里执行测试和复扫；失败则报告失败，不要自动应用。
