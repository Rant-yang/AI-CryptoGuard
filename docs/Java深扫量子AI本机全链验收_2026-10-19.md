# 公开 Java 样例的本机全链验收（2026-10-19）

## 为什么补做

此前快扫、CrySentry 深扫、量子规则、云端 AI 和离线报告各自已有验收，但它们在**同一任务**中串联的证据较弱。本次只使用仓库内故意不安全、没有真实凭据的 `examples/java_deep_demo/Demo.java`，已编译产物和运行结果均放在仓库外；第三方 CrySentry、JDK 与模型密钥都没有进入源码仓库。

此次运行覆盖的是本机公开样例的功能闭环，**不是**同口径独立准确率、陌生项目的兼容性证明，也不是另一台机器上同时配置 CrySentry 与真实云模型的复现。

## 运行方式

先按[公开样例说明](../examples/java_deep_demo/README.md)用 JDK 17 把 `Demo.java` 编译为仓库外的 `demo.jar`，并准备仓库外的三项扫描工具。模型配置只通过环境变量提供，不写入命令、日志或本文件。预检：

```cmd
python setup\preflight.py --tools-dir <外部工具目录> --target examples\java_deep_demo --mode deep-java --crysentry-home <CrySentry目录> --crysentry-java <JDK17的java.exe> --java-artifact <demo.jar> --ai --compatible-api
```

本机预检 **18/18 PASS**。正式运行：

```cmd
python core\pipeline.py examples\java_deep_demo --mode deep-java --tools-dir <外部工具目录> --java-artifact <demo.jar> --crysentry-home <CrySentry目录> --crysentry-java <JDK17的java.exe> --ai --ai-context full --ai-checkpoint 1 -o <仓库外结果目录>
python core\schema\validate_v02.py <仓库外结果目录>\findings_explained.json
python core\report.py <仓库外结果目录>\findings_explained.json --task <仓库外结果目录>\task.json -o <仓库外结果目录>\report.html
```

初次尝试在受限网络环境中仅云端请求报 `APIConnectionError`：本地凭据/配置解释 1 条完成，模型解释 1 条失败；扫描、深扫和量子评估仍保留。随后在可联网环境用 `--ai-resume` 补跑，任务变为 AI 2 条成功、0 失败、1 条复用。失败文件只记录安全错误类别，没有记录密钥或异常原文。

## 修复过程中发现的真实问题

初次完整运行把 `AES-ECB` 检出为 Finding，却把 `risk` 留成 `review`，导致量子评估写 `insufficient_evidence`。原因是该次 CryptoScan 的 `type` 不在初版词表，快扫融合直接回退 `review`；而 Java 深度适配器已经使用 `core/rules/algorithm_risk.py` 的确定性算法表，后者明确把 ECB 判为 `broken`。

现已在 `scanner/merge.py` 加入保守的第三顺位：没有 cbom-scan 风险、也没有可用的 CryptoScan `type` 规则时，只有**存在明确算法名**才查同一张算法规则表；真正未知算法和无算法线索仍保留 `review`。新增自检覆盖 `AES-ECB → broken` 与未知算法仍为 `review`。上游的 `quantumRisk` 仍不作事实来源。
