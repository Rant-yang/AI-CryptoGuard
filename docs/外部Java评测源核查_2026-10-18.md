# 外部 Java 评测源核查（2026-10-18）

目标：寻找一批此前未用于调规则、同时提供源码、可编译产物或可重复编译步骤、逐例真值的 Java 样本，以相同的 `(文件, 算法, 用途)` 口径比较 fast 与 deep-java。**下列候选尚未形成这样的正式留出集，不能据此宣称达到了方案的 Precision/Recall 目标。**

| 来源 | 实际提供的材料 | 目前判断 |
|---|---|---|
| [TSE-2022 作者实验仓库](https://github.com/NiSE-Virginia-Tech/TSE-2022) | MUBench、CryptoBench、OWASP 和 Apache 项目的多种**检测工具输出**；Apache 部分提供项目地址/提交号 | 本地只核实了目录和 README；不能把任一工具输出当作独立真值。若使用，必须另找原始标签、对应源码版本并逐例对齐。 |
| [MASC 作者仓库](https://github.com/Secure-Platforms-Lab-W-M/MASC) | Java/Android 密码误用变异**生成器**、配置和测试素材；可按配置生成带已知变异位置的样本 | 可以设计新的压力测试，但不是现成的、与本项目 Finding 单位一致的留出集。生成前须冻结配置、正负例和匹配规则；生成后不能按结果挑题。 |
| [MUBench 作者仓库](https://github.com/stg-tud/MUBench) | 已知 API 误用的真实项目数据和评测框架 | 范围是广义 API 误用，需先筛出密码相关、可获得同版源码/编译产物且能对齐本项目单位的例子。尚未完成这个筛选。 |
| [CryptoScout Zenodo 工件](https://zenodo.org/records/17074764) | 说明提及五套 ground-truth benchmark | 记录的文件为 **restricted**，不能把说明中的目录结构当作已取得数据。 |

现有正式记录仍分别陈述：[开发集与独立 OWASP 诊断](性能与评测口径.md)、[固定 25 例 Java 同题对照](Java深度同题对照_2026-10-18.md)、[真实 Apache 模块运行](Java深度真实项目验收_2026-10-18.md)。25 例对照的快扫与深扫指标相同；Apache 运行只证明工具执行与证据融合，标签/源码/行号不对齐，不能报 P/R。

下一步按时间优先级处理：

1. 不把上述仓库的检测工具输出转成“真值”，也不把同一批调过规则的样本重新命名为独立留出集。
2. 若比赛前取得**未接触的新源码和逐例标签**，先保存来源提交与许可证，冻结纳入标准、匿名化映射、匹配单位和正负例，再运行扫描；同时记录快/深完成率、超时、耗时及新增 TP/FP。无法满足这些条件就只做定性演示。
3. 在最终答辩材料中按现有证据报告开发成绩、OWASP 文件级首次诊断、25 例 Java 对照、真实模块运行四个不同口径；不要合成一个“最终准确率”。

本核查没有修改扫描器或提升指标，只是防止来源与口径误用。仓库外的研究工件不参与产品打包。
