# 本地快速扫描性能复验（2026-10-19）

目标来自初期方案 §2：普通中小项目本地检测平均不超过 30 秒；云端 AI 耗时另计。本记录测的是**统一入口从新 Python 进程启动到退出的墙钟时间**，包括快速扫描、前置量子评估及结果写入，`--mode fast`、AI 关闭，CrySentry 跳过。不是独立机器或任意项目的性能保证。

## 固定输入与环境

| 项目 | 固定值 |
|---|---|
| 测量机器 | Windows 11 10.0.26200；AMD Ryzen 9 8945HX；31.8 GiB RAM |
| 运行时 | Python 3.11.9、Node.js v24.13.0；CryptoScan 1.4.0（build commit `11f0e46`）；cbom-scan `bcf71292816aa64d5890207466b5dff1f5ef9cf7` |
| CryptoAPI-Bench | 外部 checkout `e6b6b50fef6970151300c1ac2de62e188ba6de19`；203 个 Java 文件、165,377 源码字节 |
| CamBench | 外部 checkout `3c5aeb7151fbee0074520a3730f71d299e18b20d`；623 个 Java 文件、1,014,200 源码字节 |
| 工具来源 | 第三方工具在仓库外的本机 `_smoke/`；所有扫描产物写入本机私有目录，不入 Git |

测试前 `setup/preflight.py` 对 CryptoAPI-Bench 快速模式的 6 项检查全部通过。每次使用新的输出目录、**新的 Python 进程**，同一输入目录重复运行；未清理文件系统或操作系统缓存，机器后台负载也未固定。计时器为 PowerShell `System.Diagnostics.Stopwatch`，记录子进程完整退出耗时；只有退出码为 0、`scan` 和 `quantum_assessment` 为 `completed` 的运行才计入。

复现单次扫描：

```powershell
cd D:\code_competition\AI-CryptoGuard
$sw = [System.Diagnostics.Stopwatch]::StartNew()
python core/pipeline.py D:\code_competition\_benchmarks\CamBench --mode fast --tools-dir D:\code_competition\_smoke -o C:\Users\lenovo\acg-perf-recheck
$sw.Stop()
$sw.Elapsed.TotalSeconds
```

## 定位、改动与同输入回归

`core/schema/validate_v02.py` 原先对**每一条** Finding 重新读入、解析、检查同一份冻结 JSON Schema，再实例化校验器；`core/quantum_assessment.py` 在每条 Finding、每个迁移候选上反复读取同一份量子规则 JSON。CamBench 的 661 条结果使这些不变操作被重复数百次。

现在每个 Python 进程内只为 Finding/Task 分别加载并检查一次 v0.2 Schema，量子规则也只读取一次。运行中契约与规则视为固定；**编辑这两个 JSON 文件后须重启进程**。逐条数据校验、跨字段校验、风险分派和输出格式没有放宽。

对修正前**同一份** CamBench `findings.json`，通过统一入口的 `--findings` 与原源码根重算前置评估：661 条 `findings_assessed.json` 与修正前结果解析后**逐项相等**。不能直接对新的全流程输出做字节级比较，因为凭据指纹每次扫描使用新的进程内 HMAC 密钥；因此另外比较了三次全流程的 `(finding_id, risk, quantum_effect)` 集合，均相同、每次 661 条。`core/schema/selftest_v02.py` 的 13 个有效夹具和 9 个无效变异、`core/selftest.py`、`ai/selftest_v02.py` 均通过。

| 样本 | 修正后次数 | 墙钟时间 | 平均 | 同次量子评估阶段 |
|---|---:|---|---:|---|
| CamBench | 2 | 23.26 / 21.99 秒 | **22.63 秒** | 0.72 / 0.69 秒 |

两次修正后运行的 `scan` 阶段仍为 18.015 / 17.057 秒，说明本轮节省的主要是前置评估中的固定文件重复校验。**对这个 623 文件样本、这台机器和当前工具版本，平均从 41.38 秒降至 22.63 秒，并落在 30 秒内。**修正前后的两组运行次数少，且未控制缓存与系统负载，不能把差值写成普适加速倍数，也不能推出更大项目、别的机器或深扫/云 AI 的时限。
