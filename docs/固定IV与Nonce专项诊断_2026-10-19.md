# 固定 IV / Nonce 专项诊断（2026-10-19）

本轮在 Python AST 层新增两个互不混淆的配置规则，不改变原有算法/凭据开发集评分口径。规则由本项目实现；`cryptography`、PyCryptodome 和外部基准均为第三方。

| 规则 | 证据条件 | 不报告的情况 | 依据 |
|---|---|---|---|
| `PY-CBC-FIXED-IV-DIRECT` | Python `cryptography` 的 AES-CBC `encryptor()`，或 PyCryptodome AES-CBC `encrypt()`，并能在同一线性作用域定位到 16 字节固定字面量 IV。允许简单局部 `iv` 与 `cipher` 赋值传播。 | 仅解密、动态 IV、跨分支/跨函数无法证明的值、别名被重绑定。 | [NIST SP 800-38A](https://csrc.nist.gov/pubs/sp/800/38/a/final)、[cryptography CBC API 文档](https://cryptography.io/en/latest/hazmat/primitives/symmetric-encryption/)、[PyCryptodome AES API 文档](https://pycryptodome.readthedocs.io/en/stable/src/cipher/aes.html) |
| `PY-GCM-FIXED-NONCE-DIRECT` | Python `cryptography` 的 `AESGCM.encrypt()`，且同一线性作用域可定位 12 字节固定字面量 Nonce。 | `decrypt()`、动态 Nonce、跨分支/跨函数无法证明的值。**单个调用点不证明运行时发生同一密钥下的重复使用。** | [NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)、[cryptography AESGCM API 文档](https://cryptography.io/en/stable/hazmat/primitives/aead/) |

两个规则都只存 API 名称、行号和字节数，不存 IV/Nonce 原文、密钥或源码行；扫描输出为独立的 `configuration/not_applicable` Finding，量子评估不生成 PQC 路线，AI 阶段在本地引用 E1 解释。Web 与离线 HTML 报告显示独立名称。源码里保留 `DIRECT` 规则 ID，是指固定值可以由 AST 直接证明或经同作用域线性赋值追踪；不声称跨函数数据流分析。

## 可复验结果

1. `python scanner/selftest.py` 中有直接、简单局部传播、解密、动态值、分支重赋值、别名遮蔽、注释/字符串等正负夹具；`python ai/selftest_v02.py` 验本地解释、E1 和零云调用。
2. 仓库外自建静态夹具 `C:\Users\lenovo\acg-iv-nonce-e2e-20261019\sample.py` 经正式 `scanner/scan.py` 得到**2 条**，分别是固定 CBC IV 和固定 GCM Nonce；解密与动态参数不报。统一入口 `core/pipeline.py --ai` 得到 2/2 `explained`、v0.2 合约错误 0、AI 阶段本地完成；离线 HTML 报告生成成功。该夹具只证明回归行为，不是外部准确率。
3. 另对既有匿名化 LLM-CMT Python 子集作**开发诊断**：42 个文件的标签包含 `Static IV` 或 `Predictable IV`，CBC 固定 IV 规则命中其中 6 个文件；其余 36 个未命中，多为跨函数参数、全局传播、`bytes(...)` 包装或其他库形态。扫描在标签之外未新增该规则命中的文件，但这些未标注文件**不能自动当作独立干净负例**，所以不能计算可信 Precision。GCM 固定 Nonce 在此子集没有相同口径的独立外部评估。

## 对总分的影响与限制

README 中 TP/FP/FN=620/103/62 的 P/R 是此前**冻结的算法＋凭据开发集口径**；`benchmark/scope.py` 仍把参数类 IV/Nonce 标签列为该评分任务的范围外。这组历史数字不能被称为新增参数规则后的完整系统成绩，也不能把两个任务的分母混合。若要把 IV/Nonce 纳入总体指标，必须先冻结含明确正负样本、语言/API 边界与匹配单位的新评分协议，再整体重跑。开发诊断 6/42 不得宣传为独立测试成绩。
