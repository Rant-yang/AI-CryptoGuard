## 一条建议

**决策记录比会议纪要重要。**

三个月后你们会忘记"当初为什么不用 CryptoScan 那个 `quantumRisk` 字段"，
然后有人重新踩一遍坑、或者把它改回去。

每次做了非显然的决定，**花两分钟写下来**：

```markdown
## 2026-09-28 为什么不用 CryptoScan 的 quantumRisk

它把 MD5/SHA-1/DES/3DES/RSA-1024 全标成 VULNERABLE（=量子脆弱）。
但这些都是被经典攻击攻破的，与 Shor 无关。直接采信会得出
"MD5 受 Shor 算法威胁" 的错误结论。

决定：量子风险一律由 core/rules/ 重新判定，不透传上游。
并在报告里显式打出与上游的分歧。
```

四行字，省掉未来的一次返工。

接手后的代码核查与执行顺序：见 [接手记录_2026-10-14.md](接手记录_2026-10-14.md)。该记录纠正了部分旧进度判断。
