# AI-CryptoGuard 用户手册（提交准备版）

**2026-10-19 体验更新：**扫描结束后可先看“项目总览 · 下一步做什么”，点击行动项进入对应发现；完整清单在下载的 HTML 报告中。每项的 E 编号只指向同一发现内的证据。清单是待复核、待执行的建议，不代表整改已完成。AI 连接或校验失败时，本地结果仍可查看；“仅重试 AI”不会重新扫描。若提示模型配置缺失，先配置并重启本机服务。

更新时间：2026-10-18。适用于本仓库当前 `main`。本程序面向**获授权的源码项目**；扫描结果是审计线索，整改前须由项目维护者复核。

## 1. 准备环境

快速模式需要 Python、Node.js，以及放在仓库外的 CryptoScan 与 cbom-scan。Windows 上先按 [部署说明](../setup/README.md) 准备工具，然后在 **cmd** 中运行：

```cmd
cd /d D:\code_competition\AI-CryptoGuard
python setup\preflight.py --tools-dir D:\code_competition\_smoke --target examples\repair_demo --mode fast
```

路径是本机示例，换到另一台机器时请替换。预检只验证静态前提；退出码 0 不代表实际扫描成功。容器快速模式的构建、挂载与健康检查见[部署说明](../setup/README.md#docker-compose快速扫描-web本机容器已验收)。

## 2. 用网页扫描项目

```cmd
cd /d D:\code_competition\AI-CryptoGuard
set "ACG_TOOLS_DIR=D:\code_competition\_smoke"
python web\serve.py
```

服务只监听本机 `127.0.0.1`，会自动打开页面。把**源码文件夹**拖到首页，或使用文件夹选择器。请勿把 `.env`、真实密钥、构建缓存和不相关大文件放入选择范围。浏览器上传到本机服务的 `workspace/web_tasks/`；上传限制为单文件 8 MiB、每任务 64 MiB、最多 4000 个文件。任务超过 24 小时清理，也可在页面删除任务。关闭浏览器不等于立即删除上传内容。

页面的“导入已有报告”只读取 JSON，不会重新扫描源码。扫描开始后可查看上传、本地扫描、量子评估、AI 与风险展示各阶段；`skipped` 表示该阶段没有运行，不能理解为“没有问题”。
本地任务完成后可点页眉“下载中文报告”保存离线 HTML；导入已有 JSON 时该按钮不可用，
可用 `python core/report.py <findings.json> -o <report.html> --task <task.json>` 单独导出。
下载文件只呈现归一化字段与证据编号，不含上游 `raw` 源码或凭据值；请仍按敏感审计资料保管。
报告开头列出前五条优先复核项；排序只依据严重程度、条件性标记及置信度，
不是对业务影响的自动裁定，也不代表整改已执行。

**云端 AI 默认关闭。** 勾选后，程序会先脱敏再发送上下文；`full` 模式可发送脱敏代码行，`shape` 模式只发送 API 调用形状。凭据发现始终本地处理。上传真实第三方代码或敏感项目时，应先确定该项目允许调用云模型，必要时选 `shape` 或关闭 AI。缺少模型配置时，扫描和本地量子评估仍可完成，详情页会明确显示解释未生成。

## 3. 看懂一条发现

列表里的风险是**成因**：`shor` 表示公钥算法受量子直接威胁，`broken` 表示已被经典攻击攻破，`grover` 表示量子搜索削弱强度，`review` 表示尚不能确定；凭据、配置等非算法问题使用 `not_applicable`。不要把颜色当作唯一结论。

点开一条发现可看文件、行号、严重程度、证据与整改。`E1`、`E2` 等编号对应本条发现的 `evidence[0]`、`evidence[1]`；AI 的引用应能指回这些证据。`decided: false` 和“用途待定”意味着现有证据不足以决定具体迁移路线，不是页面故障。RSA 等公钥算法要先确认签名、加密或密钥交换用途，再选择 ML-DSA/SLH-DSA 或 ML-KEM 路线。

Java 深度模式中的 `partial` 流程只证明已定位的首尾位置；如果没有中间传播路径，不能当作完整 source→sink 证明。弱随机密钥配置问题的[公开示例](../examples/java_deep_demo/README.md)给出了这一边界。

## 4. 用命令行生成报告

快速扫描与前置量子评估：

```cmd
cd /d D:\code_competition\AI-CryptoGuard
python core\pipeline.py examples\repair_demo --tools-dir D:\code_competition\_smoke -o out\demo_fast
python core\schema\validate_v02.py out\demo_fast\findings_assessed.json
```

结果在 `out\demo_fast\findings_assessed.json`，任务状态在 `task.json`。若显式追加 `--ai`，成功时另有 `findings_explained.json`；模型配置只放环境变量，不写到命令、日志或仓库。量子时间窗口可用 `--data-lifetime-years X --migration-lead-years Y --threat-horizon-years Z --hndl-exposure yes|no|unknown` 指定，三项年数要一起给，不会猜一个默认“量子危机日期”。

Java 深度模式需要**与源码对应的已编译 jar/classes**、仓库外 CrySentry 和 JDK 17：

```cmd
python core\pipeline.py examples\java_deep_demo --mode deep-java --tools-dir D:\code_competition\_smoke --java-artifact D:\path\to\demo.jar --crysentry-home D:\code_competition\_smoke\CrySentry --crysentry-java D:\path\to\jdk-17\bin\java.exe -o out\demo_java
```

不要把第三方分析器、JDK、用户源码、扫描原始输出或真实凭据提交进仓库。深度阶段失败或跳过时仍保留快速扫描结果；检查 `task.json.stages` 的状态与原因，不要把快速结果冒充深度结果。

## 5. Repair → Verify（仅候选补丁）

```cmd
python repair\verify.py examples\repair_demo\app.py --project-root examples\repair_demo --tools-dir D:\code_competition\_smoke -o out\repair_report.json
```

该命令只修改临时副本，依次检查候选补丁的编译级语法、正式 scanner 前后差异，并在显式提供受信任项目目录时运行其 `tests/` 中的 unittest。当前模板只有 Python 的 MD5、弱随机与硬编码口令三类。报告里的 `ELIMINATED` 只证明扫描发现消失；即使测试通过，也要复核协议、数据格式、依赖与部署环境。**不要对不可信项目启用 `--project-root`**：临时副本不是操作系统沙箱。

## 6. 故障与数据处理

| 现象 | 先看哪里 |
|---|---|
| 找不到第三方工具 | `setup/preflight.py` 与 `ACG_TOOLS_DIR`；工具必须在仓库外 |
| 只看到本地结果、没有 AI 解释 | `task.json.stages.ai`；AI 默认关闭，开启后还需模型环境变量 |
| Java 深度阶段 skipped/failed | 是否给了同源码编译的 jar/classes、JDK 17、CrySentry；检查可达方法与超时 |
| 页面导入 JSON 没有重新扫描 | “导入已有报告”是查看入口；要从源码扫描请使用首页项目文件夹入口 |
| 结果中的用途是 unknown | 当前证据不足；不能凭算法名推断业务用途 |

`out/`、`workspace/` 和 `.env` 已被 Git 忽略。需要立即清除 Web 上传时请在页面删除任务；清理或备份整个任务目录前先确认其绝对路径。最终汇报请引用[性能与评测口径](性能与评测口径.md)、[第三方来源](第三方来源与分发边界.md)及[项目现状](项目现状.md)，不要将开发集数字写成独立泛化成绩。
