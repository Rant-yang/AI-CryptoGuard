# AI v0.2 语义人工复核操作（2026-10-18）

> **历史批次（30 条）。** 这份操作只检验此前预先固定的 30 条公开示例。当前 TLS 规则修正后的 **28 条算法 Finding** 请使用[当前批次 AI 盲审操作](当前批次AI盲审操作_2026-10-18.md)，不能把两批结论或文件混用。

模型输出通过 JSON Schema，只证明格式可用；用途、证据引用、密码事实与整改步骤，必须由看过原始公开源码的人分别判断。审阅者不要先看历史失败清单，也不要把模型措辞当作证据。

## 数据来源和边界

- 样本 ID 固定在 `ai/semantic_eval.py` 的 `CASE_IDS`；不能按新模型答得好坏换样本。
- 输入是 CryptoScan 随附的公开 `crypto-samples`；凭据 Finding 不送云端，也不进入这 30 条。
- 生成的模型结果、评分文件和盲审包均留在 Git 忽略目录或仓库外；不要提交原始源码片段、密钥、用户项目路径或模型全文。
- 盲审包只给文件名、E 编号、调用形状/白名单摘要和模型结论。原始证据不足时，应打开对应的**公开**源码核对，不能凭包里缺少的上下文猜用途。

## 生成盲审包

在仓库根目录的 Windows cmd 中运行。前两项来自固定公开样本的扫描与评估输出；若不存在，先照 [AI 语义验收](AI语义验收_2026-10-18.md) 的复现命令生成。

**必须使用当前提示词版本生成的 v0.2 结果。** 同一组 30 个 Finding ID 曾由旧版提示词处理；仅按 ID 和 Schema 校验会把旧结果误作新结果。本机旧 `out\ai_semantic_30_explained.json` 的 `analysis_provenance.prompt_version` 是 `.1`，当前代码要求 `ai-v02-2026-10-18.2`。评分器现在会拒绝旧版本，且在拒绝时不会创建盲审包。下例把当前真模型输出路径交给 `ACG_CURRENT_V02`；换成审阅机器实际文件路径，不要指向旧 `out` 产物。

```cmd
set "ACG_CURRENT_V02=C:\path\to\current-v02-explained.json"
python ai\semantic_eval.py score out\ai_semantic_30_assessed.json "%ACG_CURRENT_V02%" -o out\ai_semantic_30_score.json
python benchmark\ai_semantic_review.py out\ai_semantic_30_score.json --assessed out\ai_semantic_30_assessed.json -o out\ai_semantic_30_blind_review.json
python ai\semantic_eval_selftest.py
```

随后复制盲审包给审阅者。审阅者应**独立对照公开源码**，逐条填四个布尔字段：

### 离线填写页（可选）

直接用浏览器打开 `web/semantic_review.html`（也可通过本地服务的 `/web/semantic_review.html` 访问），选择盲审包 JSON。页面显示模型结论、E 编号、脱敏后的调用形状和行号，并提供四个独立判断下拉框与备注框。它只在浏览器内存处理文件，不会上传审阅内容，也**不会代人判断对错**。审到一半时点击“导出当前审阅 JSON”保存进度；下次可重新导入这个文件继续。离开或刷新页面前务必导出。

本页面没有原始公开源码；审阅者仍需另开对应的 CryptoScan 公开样例文件，核实上下文和模型引用。审阅者不要只读页面上的模型叙述就选择“支持”。导出的 JSON 保留原盲审包格式，可直接交给下面的 `--require-complete` 命令。

编辑器自检（只检查格式和进度，不会给人工结论打分）：

```cmd
node web\semantic_review_selftest.js out\ai_semantic_30_blind_review.json 30
```

| 字段 | `true` 的必要条件 | `false` 的例子 |
|---|---|---|
| `review_usage_supported` | 用途能由该算法的调用或下游消费点支持 | 仅凭 RSA 算法名、注释或上游 `purpose` 猜签名 |
| `review_refs_support_claims` | 文中的 `E1`、`E2` 确实指向支持对应说法的证据；不能引用别的算法的行 | 文中说签名，却只引用了 ECDH 密钥协商调用 |
| `review_explanation_correct` | 密码风险、Shor/Grover/经典攻击的表述事实正确且不过度推断 | 把 MD5 的已知碰撞写成已知通用原像攻击 |
| `review_steps_actionable` | 步骤对当前场景可执行，顺序、前置条件和复验方法说清楚；具体算法来自规则库 | 任意把 RSA 换成 ML-KEM，或要求破坏协议兼容性的替换 |

每个字段只能填 `true` 或 `false`；还没看完保持 `null`。一项为 `false` 时在 `review_notes` 写明源码位置和理由。**证据缺失也填 `false`**，不要把不确定猜成通过。对同一条发现可以有多项失败。先审阅再看旧版问题清单，避免锚定。

完成后计算：

```cmd
python benchmark\ai_semantic_review.py out\ai_semantic_30_blind_review.json --require-complete
```

`--require-complete` 在 30 条没有全部填完时返回非零；输出中的 `fully_reviewed` 是实际审阅数，`all_four_supported` 是四项同时通过数。`semantic_rate` 只有在至少一条完全审阅后才有数值；**只有 30/30 全部审阅时才允许把它称为这批样本的语义通过率**。它仍不是独立真实项目的性能指标。完整原始审阅记录留在私有工作区，仓库文档只写汇总、失败类别与修复记录。

可先用以下离线自检验证计数器不会凭空填结论：

```cmd
python -m benchmark.ai_semantic_review_selftest
```
