# 8 类凭据管理缺陷：实现与验收记录

更新时间：2026-10-14。模块位于 `scanner/adapters/credential_scan.py`，属于自研能力。

## 1. 做了什么

| 规则 ID | 缺陷类别 | 主要证据 |
|---|---|---|
| `CRED-HARDCODED-PASSWORD` | 硬编码口令 | 敏感变量接收字面量 |
| `CRED-HARDCODED-TOKEN` | 硬编码 API Key / Token / Secret | Token 类变量接收字面量 |
| `CRED-HARDCODED-CRYPTO-KEY` | 硬编码密码学密钥 | 密钥变量 + 密码 API 文件上下文 |
| `CRED-EMBEDDED-PRIVATE-KEY` | 源码内嵌私钥材料 | 私钥 PEM 头 |
| `CRED-IN-URL` | URL / 连接串中包含凭据 | `scheme://user:password@host` 形态 |
| `CRED-IN-LOG` | 凭据进入日志或标准输出 | 日志 sink 引用敏感变量 |
| `CRED-DEFAULT-WEAK` | 默认或弱口令 | 敏感变量 + 弱口令词表 |
| `CRED-HIGH-ENTROPY-SECRET` | 敏感变量中的高熵秘密 | 敏感变量 + 长度/熵联合判断 |

这些是 8 种**管理缺陷**，不是把 8 家云厂商的 Token 前缀当作 8 类。

## 2. 为什么不把它们当算法

旧 Finding 只有算法风险轴。凭据问题若硬塞进去，会重新出现“Mutual TLS 被当成
算法名”一类错误。Schema 因此新增了兼容字段：

- `finding_kind: credential`
- `rule_id: CRED-...`
- `risk: not_applicable`：表示不属于 Shor/Grover/经典算法风险轴

旧算法 Finding 不带 `finding_kind` 时仍按 `algorithm` 处理，不需要迁移旧数据。

## 3. 隐私约束

检测结果中**永远不保存凭据原文**：

- `masked` 只显示长度，例如 `<REDACTED:length=32>`；
- `fingerprint` 是用进程内随机密钥计算的 HMAC-SHA256；随机密钥不落盘；
- Finding ID 由文件、规则、行列位置生成，跨扫描稳定；
- 日志类问题的证据也不保存整行源码；
- 真实 Key / Token 不写控制台，不进入 Git，不进入云端请求。

`python scanner/credential_selftest.py` 会用合成数据反向断言：八类全部命中、
Finding ID 稳定、HMAC 每次变化、Schema 合规、输出 JSON 找不到任何合成凭据原文。

## 4. 已接入的位置

`scanner/scan.py` 每次扫描都会运行 `credential-scan`。凭据 Finding：

- 与算法 Finding 一起写入主 `findings.json`；
- 不参与算法 merge，也不进入 CBOM；
- 已带本地规则解释、`evidence_refs: ["E1"]` 和确定性加固建议；
- `ai/enrich.py --resume` 会识别它已完成增强，不再把凭据发给大模型；
- `web/` 用规则 ID 展示，风险显示为“非算法风险”。

## 5. 当前公开 benchmark 实测

三个已扫描匿名语料中，凭据专项：

| 指标 | 当前值 |
|---|---:|
| TP / FP / FN | 102 / 111 / 120 |
| Precision | **47.9%** |
| Recall | **45.9%** |
| F1 | **46.9%** |

整体算法 + 凭据口径：P=67.3%、R=71.5%、F1=69.3%。该数字比只算算法时低，
因为 7 个公开凭据类别从“范围外”正式进入了考卷，不能再用旧的 75.2% / 82.2%
代表完整系统。

## 6. 已知限制与下一步

1. CryptoAPI-Bench 的 `credentialinstring` 包含“随机生成后仍保存在 Java String”
   的问题，不等价于硬编码；当前模块只覆盖其中一部分。
2. LLM-CMT 的 `hardcoded` 是宽泛标签，既有直接字面量，也有测试代码、配置项和
   跨函数传播；当前轻量上下文分析尚未全部覆盖。
3. 当前 111 个 FP 需要按“真实误报 / benchmark 标签粒度 / 同文件多规则”拆分，
   不能靠删样本提高数字。
4. 下一轮优先补：直接 API 参数字面量、跨行数组/私钥常量、配置文件键值，随后
   建独立留出集，避免只对公开 benchmark 调规则。
